# ContextVocab 开发SOP（产品视角）

## 1. 目的
- 把“想法 -> 需求 -> 开发 -> 验证 -> 上线 -> 复盘”流程标准化
- 降低临时决策带来的返工与质量波动

## 2. 角色分工
- AI 产品经理（你）：
- 定义问题与目标指标
- 拆解优先级与验收标准
- 复盘迭代结果并决定下一轮方向

- 开发执行（你或协作同学）：
- 按 SDD 实现
- 保证日志、埋点、容错
- 输出变更说明和测试结果

## 3. 需求进入流程（每次迭代必须过）
- Step 1：写 1 页需求卡（最多 10 分钟）
- 背景问题
- 用户场景
- 成功指标（至少 1 个）
- 不做什么

- Step 2：定义验收标准（DoD）
- 功能可用
- 数据可观测
- 错误可降级
- 文案与交互一致

- Step 3：评估优先级
- P0：主链路成功率问题
- P1：学习效果提升
- P2：体验增强

## 4. 开发执行SOP
- 4.1 开工前
- 同步更新 `docs/plan.md` 对应阶段项
- 在需求中写明数据影响：会改哪些 localStorage key

- 4.2 编码中
- 先接入埋点，再做 UI
- 所有外部请求必须有超时和错误提示
- 不破坏已有核心链路（阅读/点词/卡片/复习）

- 4.3 提交前检查
- `npm run build` 必过
- 手工回归主流程
- 输出“改了什么 + 如何验证”

## 5. 测试SOP（最小可执行）
## 5.1 功能回归清单
- 首页可选题、可上传
- 阅读页可点词出卡
- 加词库按钮可写入且状态正确
- 练习可判题并出结果
- 错词进复习并可完成调度
- 词库页可展示、可导出

## 5.2 稳定性清单
- 断网/超时时是否有 fallback
- OpenRouter 异常时是否仍可学习
- PDF 导入失败是否给出可操作提示

## 5.3 数据一致性清单
- 词库、复习、缓存 key 是否统一
- 旧缓存是否兼容升级
- 删除词是否影响复习和导出

## 6. 埋点与指标SOP
- 必打事件：
- `word_click`
- `card_response`
- `card_error`
- `wordbook_add`
- `review_session_complete`

- 每周固定产出：
- 3 秒出卡率
- fallback 比例
- 中文释义可用率
- 次日复习完成率

## 7. 内容导入SOP（真题）
- Step 1：上传 PDF 自动解析
- Step 2：检查质量警告（完整率/异常率）
- Step 3：必要时人工校对
- Step 4：保存并抽样点词验证
- Step 5：记录导入报告（日期、套题、问题、处理）

## 8. 发布SOP
- 发布前：
- 冻结需求 24h
- 完成回归清单
- 保存指标快照

- 发布后：
- 观察 24h 指标波动
- 记录异常事件与修复动作

## 9. 复盘模板（每轮必写）
- 本轮目标是什么
- 指标变化如何（前后对比）
- 失败/偏差原因是什么
- 下一轮要保留/删除/新增什么

## 10. 简历资产沉淀SOP
- 每轮保留三类证据：
- 指标截图（前后对比）
- 关键交互截图（功能证据）
- 决策说明（为什么这样做）

- 每月整理一次项目案例包：
- 项目背景（1页）
- 方案与架构（1页）
- 数据结果与复盘（1页）
