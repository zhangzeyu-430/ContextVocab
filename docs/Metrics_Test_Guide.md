# 指标测试手册（Metrics Test Guide）

## 1. 目标
- 让你可重复地产出以下量化指标：
- North Star：D1 复习完成率
- 单词加入词库率
- 3 秒内出卡成功率
- 中文释义可用率

- 分层看板：
- 技术层：API 成功率、fallback 率、超时率
- 内容层：错义率、中文可读率、用户纠错率
- 学习层：复习“我会”比例、次日留存率

## 2. 前置准备
- 启动：`npm run dev:full`
- 浏览器打开项目，右下角打开 `Dev Panel`
- 先点击 `Clear` 清空旧埋点

## 3. 一轮标准测试（建议 20~30 次点词）

## 3.1 阅读与出卡
- 进入任一阅读文章
- 连续点击 20~30 个词（包含常见词和生词）
- 对每个词尽量等待卡片返回

你会在 Dev Panel 看到：
- 3秒出卡率
- API成功率
- fallback率
- 超时率
- 来源拆分（cache / dictionary / openrouter / fallback）

## 3.2 内容质量反馈
- 对每个卡片点击 `解释准确` 或 `解释不准`
- 至少反馈 10 次

你会在 Dev Panel 看到：
- 错义率（解释不准 / 全部反馈）
- 中文可读率（card_response.hasChinese）

## 3.3 词库与纠错
- 挑 10 个词点击 `加入词库`
- 去词库页移除 2~3 个“加错”的词

你会在 Dev Panel 看到：
- 词库加入率（wordbook_add / word_click）
- 用户纠错率（wordbook_remove + 解释不准）/ word_click

## 3.4 练习与复习
- 在阅读页完成练习
- 进入复习页，至少做 10 题，混合点击“我会/我不会”

你会在 Dev Panel 看到：
- 复习“我会”比例（knownRate）
- D1复习完成率（nextDayReviewCompletionRate）

## 4. 如何看结果（判读口径）

## 技术层
- API成功率 >= 80%：主链路稳定
- fallback率 <= 20%：依赖退化可控
- 超时率 <= 25%：时延可接受
- 3秒出卡率 >= 85%：交互体验达标

## 内容层
- 中文可读率 >= 80%：可学性达标
- 错义率 <= 12%：语义质量较稳
- 用户纠错率 <= 20%：入库与解释质量可控

## 学习层
- 词库加入率 >= 15%：说明内容有学习价值
- 复习“我会”比例 >= 60%：记忆效果可接受
- D1复习完成率 >= 60%：闭环有效
- 次日留存率 >= 35%：用户有持续学习意愿

## 5. 出简历数字的方法
- 每次测试前 `Clear`
- 固定同一批文章、同一测试时段
- 连续跑 3 轮，取均值
- 在简历写法中同时给“前后对比”：
- 例如：fallback 率从 38% 降到 17%
- 3 秒出卡率从 62% 提升到 86%

## 6. 常见问题
- Q：D1 指标为什么是 0？
- A：你当前会话里没有满足“次日”条件的复习完成数据，先做跨天样本或模拟 next-day 数据。

- Q：错义率为什么没变化？
- A：必须点击 `解释准确/不准` 才会计入内容层反馈指标。

- Q：词库加入率偏低怎么办？
- A：先优化入词提示与词卡价值感，再看加入率是否提升。
